# Database model

Prisma is the schema authority. Run committed migrations with `npm run db:migrate`; never use `db push` in production. PostgreSQL 17 is used locally.

| Entity | Purpose and constraints |
| --- | --- |
| User | Unique normalized email, password hash, fixed CUSTOMER/OPERATOR/ADMIN role |
| Session | Unique digest, separate CSRF token, expiration, cascade on user deletion |
| Destination and Attraction | Localized content, distinct slugs, coordinate verification flag |
| Tour and TourImage | Publication status, multilingual content, services, ordered gallery |
| ItineraryDay and Waypoint | Unique tour/day and day/position, distinct attraction foreign keys |
| Departure | Unique tour/date, active pricing, capacity, reserved counter and publication flag |
| Booking | User and departure foreign keys, unique user/idempotency key, immutable price snapshot |
| BookingHistory | Actor, status and timestamp for every state change |
| Review | One per booking, rating constraint 1–5, moderation required |
| Notification | Unique booking/event, customer ownership and read timestamp |
| Outbox | Durable event payload and delivery timestamp |
| AuditLog | Staff/customer actor, operation, entity and non-secret metadata |
| Message | Thread owner, authenticated sender, bounded body, timestamp |
| Media | Object key, multilingual description, processed dimensions and size, uploader |
| Setting | Explicitly allowlisted localized operator settings |

Foreign keys use Restrict for commercial records and Cascade for dependent session/content records. Tours are archived instead of deleted. Booking and history records are never hard-deleted by the application. Privacy retention and deletion procedures must be agreed before real customer operation.

Localized scalar content and departure pricing use bounded, validated JSON. Arrays of services and the cost breakdown intentionally remain part of the configuration snapshot rather than separate mutable accounting tables. A full payment ledger, participant identity records, arbitrary permission records, discount schedules and supplier accounting are not created as empty placeholder tables.

Four migration directories cover the base model, private messages, media and notification uniqueness. The base migration adds capacity, participant, tour-limit and rating checks. UUIDs are generated by Prisma. Main access patterns have supporting indexes.

The initial tour keeps the Sultan Uvays and Khojayli Gyaur Kala attractions as different rows and different slugs. Supplied road distances and historical dates were not promoted to verified production data. Seeded coordinates are approximate and carry `verified=false`.

Use a dedicated database ending in `_test` for integration and browser tests. Tests append uniquely identified fixtures and never truncate the development database. Local fixture data can be removed by recreating only the disposable test database after test processes stop.
